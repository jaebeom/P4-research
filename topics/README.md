# topics

P4 **주제 후보**를 조사하고 비교하는 곳이다. 주제는 아직 정해지지 않았다.

기준은 하나다: **측정 가능한 효과가 가장 큰 안을 고른다.** 그래서 후보마다 "문제가 얼마나 큰지"를 숫자와 출처로 보여야 한다.

## 후보 한 개를 조사하는 틀

후보마다 파일 하나(`<slug>.md`)를 만들고 아래 항목을 채운다.

| 항목 | 쓸 내용 |
|---|---|
| 한 줄 설명 | 누가 겪는 어떤 문제를 어떻게 푸는가 |
| 상황 (수치) | 문제의 크기. 숫자, 출처, 확인일 |
| 지금의 방식 (As-Is) | 현재 사람이 어떻게 처리하는가 |
| Pain Point (수치) | 시간, 비용, 오류, 위험 중 무엇이 얼마나 문제인가 |
| 해결 아이디어 | 우리 기술로 어떻게 푸는가 (AMR 주행, 객체 인식, 시스템 모니터링 등) |
| 측정 가능한 효과 | KPI / Baseline / Target / 측정 방법 |
| 기술 적합성 | TurtleBot4, YOLO, 우리 환경에서 가능한가 |
| 위험과 미확인 | 데이터 확보, 시간, 성능 한계 |
| 출처 | 링크와 확인일 |

## 후보 비교표

후보가 모이면 같은 기준으로 비교한다. 점수 기준과 가중치는 **결과를 보기 전에** 정한다.

**기준과 가중치 (2026-10-03, 점수를 매기기 전에 정함).** 각 기준을 1 ~ 5점으로 매기고, 가중 점수 = Σ(가중치 × 점수) ÷ 5 (100점 만점)다.

| 기준 | 가중치 | 5점 | 1점 |
|---|---|---|---|
| 효과의 크기 (수치 근거) | 30 | 출처 있는 baseline 숫자가 있고 효과가 크다 | 숫자가 없거나 가상 예시뿐이다 |
| 평가표 적합성 | 25 | 과정 평가표의 통합 항목(장애물 회피·도킹, 탐지·depth·이동, 장애 처리, 상태 감시, 통합)이 시나리오 안에서 자연스럽다 | 억지로 끼워야 한다 |
| 기술 적합성 (실측 한계 안) | 20 | 아래 "공통 실측 제약" 안에서 시연할 수 있다 | 제약을 크게 넘는다 |
| 구현 난이도·데이터 확보 (새 작업량) | 15 | 새 클래스, 소품, 기능이 거의 없다 | 라벨링과 새 기능이 많다 |
| 위험 (안전, 개인 정보) | 10 | 사람이 대상이 아니다 | 로봇이 사람에게 다가가고 사람 사진을 다룬다 |

| 후보 | 효과의 크기 (30) | 평가표 적합성 (25) | 기술 적합성 (20) | 구현 난이도·데이터 (15) | 위험 (10) | 종합 |
|---|---|---|---|---|---|---|
| [A 물류창고 통로 낙하물](warehouse-aisle.md) | 2 가상 예시뿐 | 5 | 4 | 3 우회 기능 | 5 | 72 |
| [B 방치 물품 원격 확인](abandoned-items.md) | **5** 한 해 1,600개, 하나에 30분 이상 | 4 | 4 | 2 새 클래스 | 3 | 78 |
| [**C 소방차 전용구역 막힘 확인**](fire-lane.md) | 3 법과 사고 사례 (점수를 매긴 뒤 추가 조사: 문제 크기 숫자는 찾았고, KPI의 baseline은 추정) | **5** | 4 | **5** 새 클래스 없음 | **5** | **84** |
| [D 작업자 위험구역 진입](hazard-zone.md) | 2 숫자 없음 | 3 | 2 움직이는 대상 | 4 | 1 | 49 |

- 점수는 작성자의 판단이다 (추정). 팀이 각자 매긴 뒤 평균을 내는 것을 권한다.
- **민감도:** 효과의 가중치를 40, 구현 난이도·데이터를 5로 바꾸면 B 84, C 80으로 순위가 바뀐다 (추정: B = (5×40 + 4×25 + 4×20 + 2×5 + 3×10) ÷ 5 = 84, C = (3×40 + 5×25 + 4×20 + 5×5 + 5×10) ÷ 5 = 80). 즉 **C를 고르려면 C의 baseline 숫자를 구하는 것이 조건**이다.

## 추천 (2026-10-03)
**C [소방차 전용구역 막힘 확인](fire-lane.md).** 단, 다음 주 화요일 주제 마감 전에 C의 baseline 숫자(막힘이 얼마나 오래 가는지 등)를 구해야 한다. 구하지 못하면 **B [방치 물품](abandoned-items.md)** 으로 간다.
- **조건의 현재 상태 (2026-10-03 추가 조사, [baseline 노트](../notes/2026-10-03-fire-lane-baseline.md)): 부분 충족.** 적발이 주민 신고로 이뤄진다는 출처가 있어 "사람 신고 없이 확인된 막힘의 비율"을 같은 지표로 baseline(0%, 추정)과 효과에 쓸 수 있다. 막힘 지속 시간과 발견까지의 시간은 미확인이다. 이 가정 baseline이 인정되는지 튜터에게 확인한다 (아래 질문 5). 점수는 결과를 본 뒤 바꾸지 않았다. 두 후보는 핵심 흐름이 같아서 바꾸는 비용은 이야기와 탐지 클래스 정도다.
- C: 미니 프로젝트의 두 클래스(RC카, 검은 상자)를 "불법 주차 차량"과 "적치물"로 그대로 쓰고, 평가표의 통합 항목을 시나리오가 자연스럽게 덮고, 멈춰 있는 대상이라 우리 실측 한계에 맞는다. 도킹해 있다가 출동해서 배터리에도 유리하다 (추정).
- B: baseline이 가장 좋지만 새 클래스와 소품이 필요하고, "주인 없음"을 사람 탐지로 판단하면 개인 정보 규칙이 붙는다.
- A: 강사 예시와 주제가 겹치고 baseline이 가상 예시뿐이다. 우회 기능이 일정 위험이다.
- D: 로봇이 사람에게 다가가는 안전 문제와 개인 정보 문제가 가장 크다.

## 모든 후보에 공통인 것
**흐름.** 과정이 요구하는 흐름은 "고정 카메라가 대상을 찾음 → 로봇 출동 → 도착 → 로봇 카메라로 대상을 찾음 → 접근"이다 (인용: 강사 Day 2 슬라이드의 미니 프로젝트 예시 흐름도 [1]). 최종 프로젝트는 여기에 상태 감시, 로봇 여러 대, 장애 처리를 더한다 (인용: 강사 Day 1 슬라이드의 평가 지표 [1]. 슬라이드에 7기 표기가 있어 9기 배점은 미확인). 그래서 네 후보 모두 **"금지 구역에 대상이 T초 이상 머묾 → 경보 → 로봇이 가서 확인 → 증거 보고 → 복귀와 도킹"** 을 쓰고, 주제가 바꾸는 것은 이야기, baseline, 탐지 클래스, 소품, 안전 규칙이다.

**평가표와의 대응** (인용 [1], 150점 중): Detection Alert 10, AMR Controller 10, System Monitor 10, 통합 시험의 장애물 회피·도킹·도착 10, 객체 감지·depth 변환·이동 10, 실시간 장애 처리 10, System Monitor 완성 품질 10, 시스템 통합 수준 20.

**공통 실측 제약**

| 제약 | 값 | 구분 |
|---|---|---|
| 로봇 영상 | 1280x720 압축, 18.8 ~ 21.3 Hz, 3.91 MB/s | 측정 (PC에서 `ros2 topic hz`, `ros2 topic bw`, 2026-10-02. [Pi 프로파일 노트](../notes/2026-10-02-turtlebot4-pi-profile.md)에 21.3 Hz) |
| 영상 대역폭 | 1대 약 31 Mbit/s, 2대 약 63 Mbit/s. 교실 Wi-Fi 용량은 미확인 | 추정 (3.91 MB/s × 8, 그 × 2) |
| 실시간 처리 | 로봇 영상에서 14.9 fps | 측정 (탐지 노드의 처리 통계, 2026-10-02 ~ 03) |
| 처리 손실 | 입력의 약 30%를 처리하지 못한다. 원인은 미확인 | 추정 (1 − 14.9 ÷ 21) |
| 배터리 | 정지·영상 구독 중 0.7 ~ 1 %p/분. 주행 중은 미확인 | 측정 (`battery_state`, 2026-10-02, 2구간) |
| 도킹 중 센서 | 카메라와 LiDAR가 꺼진다 | 측정 (설정 파일 읽기: 로봇의 `turtlebot4.yaml`, `power_saver: true`) |
| 자동 꺼짐 | 도킹하지 않은 채 12% 이하로 60초가 지나면 꺼진다 | 인용 [2] |
| Depth | 보류 중 (비공개 ROKEY_P4의 DEC-005). 켜면 원본 약 55 MB/s | 추정 (1280 × 720 × 2 B × 30 fps) |
| 위험 신호 | 충돌, 낭떠러지 같은 위험 신호가 기본 설정에서 밖으로 나오지 않는다 | 측정 (설정 파일 읽기: 로봇의 `republisher.yaml`, 2026-10-03) |
| 데이터 | 데이터 A 101장, `box` 25개, `car` 82개 | 측정 (`split_report.json` 읽기, 2026-10-03) |
| 로봇 2대 | 두 팀 로봇의 네트워크 구성이 아직 정해지지 않았다 | 비공개 ROKEY_P4의 DEC-010 |

그래서 **멈춰 있는 대상, 도킹해 있다가 출동, 확인할 때만 영상 수신**이 유리하다 (추정).

## 튜터에게 확인할 것
1. 미니 프로젝트 대상(RC카, 검은 상자)을 최종 프로젝트에서 의미를 바꿔(불법 주차 차량, 적치물) 써도 되는가?
2. 평가의 "depth 변환"은 OAK-D Depth 영상이어야 하는가, 다른 거리 측정도 인정되는가? (비공개 ROKEY_P4의 DEC-005)
3. 두 팀 로봇을 한 ROS 그래프로 묶으려고 로봇의 Discovery Server 설정을 바꿔도 되는가? (비공개 ROKEY_P4의 DEC-010)
4. 아레나에 바닥 테이프와 소품을 둬도 되는가? 아레나를 쓸 수 있는 시간은 언제인가?
5. BRD의 baseline은 공개 자료여야 하는가, 인터뷰나 근거를 밝힌 가정도 되는가?
6. 강사 예시(보안 순찰, 창고 점검)와 같은 주제도 되는가?
7. 2026-10-05(월)은 개천절 대체공휴일이고 10-09(금)은 한글날이다 (인용 [3]). 이날 수업이 있는가? "다음 주 화요일"(10-06) 마감은 몇 차시인가? (달력 사이트는 10-01도 공휴일로 표기하지만 그날도 수업이 있었다)
8. 9기 배점이 7기 표기가 있는 평가 슬라이드와 같은가?
